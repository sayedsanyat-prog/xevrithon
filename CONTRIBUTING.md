XEVRITHON — Contribution Guidelines

1. Purpose

This document explains how contributors should participate in the XEVRITHON project.

2. Contribution Principles

All contributions should follow these principles:

- Write clear and maintainable code.
- Follow the project's architecture and specifications.
- Prioritize security and correctness.
- Avoid unnecessary complexity.
- Explain important technical changes.
- Do not introduce unreviewed consensus changes.

3. Before Contributing

Contributors should:

1. Read README.md.
2. Review SPECIFICATION.md.
3. Understand ARCHITECTURE.md.
4. Check DECISIONS.md for current design decisions.
5. Review SECURITY.md and TESTING.md.

4. Code Contributions

- Keep changes focused.
- Include relevant tests.
- Document important behavior.
- Never include private keys, passwords, or secrets.
- Do not claim that untested code is production-ready.

5. Consensus-Critical Changes

Changes to transaction validation, block validation, mining, difficulty adjustment, or chain selection require careful technical review and testing.

6. Review Process

Contributions should be reviewed before being merged into the main branch.

Security-sensitive changes require additional review.

7. Current Project Status

Contribution guidelines are documented.

The contribution and review process may evolve as the project develops.
